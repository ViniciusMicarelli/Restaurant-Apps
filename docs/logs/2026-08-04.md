### 4. Busca Inteligente & Full-Text Search (ADR-006)
* Mapeados os casos de uso de busca inteligente no sistema.
* Adotada a **Estratégia Híbrida de FTS**:

  * **PostgreSQL `pg_trgm` (Trigramas) + `tsvector`** para buscas operacionais instantâneas de backoffice (comandas, clientes, pedidos e insumos).

### 5. Implementação real da plataforma (Fases 0-2 do plano de execução)

Auditoria encontrou o código ~15% pronto (7/12 serviços mockados sem
persistência, 5/12 vazios, bug de sintaxe em `packages/database/session.py`,
`generate_uuid7()` na verdade gerando UUIDv4, nenhuma suíte de testes
rodando de ponta a ponta). Trabalho executado para corrigir a fundação e
entregar o primeiro microsserviço completo:

* **`packages/*` reestruturados** para layout `src/<pacote>/` instalável via
  `uv workspace` (antes eram módulos soltos sem pacote Python real):
  `restaurant-core` (exceções RFC 7807 + `generate_uuid7()` agora um UUIDv7
  real, RFC 9562), `restaurant-security` (Argon2id, JWT com `token_type`
  access/refresh, `TenantContextMiddleware`, RBAC `require_role`/`require_tenant_id`),
  `restaurant-database` (`GUID` — tipo UUID agnóstico de dialeto SQL,
  `SQLAlchemyRepository` genérico tenant-aware, `DatabaseManager` corrigido),
  `restaurant-common` (novo — `BaseAppSettings`, `ProblemDetails`/RFC 7807
  handler, `PaginatedResponse`), `restaurant-events` (novo — `DomainEvent` +
  `EventBus` sobre RabbitMQ via `aio-pika`, para a Saga por coreografia).
  67 testes automatizados cobrindo os 5 pacotes.
* **Correções de documentação**: `ADR-001-modular-monolith` marcada como
  *Superseded*; `README.md`, `ai/architecture.md`, `ROADMAP.md`, `ADR-006`
  e `infra/k8s` corrigidos para eliminar contradições com a arquitetura de
  microsserviços vigente (ver auditoria completa nesta sessão). Criados os
  5 documentos referenciados no índice que não existiam (`architecture/system_overview.md`,
  `security/security_architecture.md`, `database/schema_design.md`,
  `testing/test_strategy.md`, `deploy/infrastructure_strategy.md`).
* **Infraestrutura dev/prod separada** (`infra/docker/docker-compose.dev.yml`
  vs `docker-compose.prod.yml`): em prod o PostgreSQL não sobe como
  container — aponta para uma instância dedicada externa via `.env.prod`;
  Redis/RabbitMQ/Meilisearch continuam containerizados em ambos. Dockerfile
  `uv` multi-stage padronizado para os 12 serviços, gateway Nginx
  (`infra/nginx/`), script de bootstrap de bancos por serviço
  (`infra/scripts/create-service-databases.sh`), `.env.dev.example`/`.env.prod.example`.
* **`auth-service` completo** (Clean Architecture: domain/application/infrastructure/presentation):
  cadastro de dono (`register-owner`, único endpoint não-autenticado) e de
  funcionários (`employees`, protegido por RBAC, sem escalação de privilégio),
  login por e-mail/senha e por PIN, refresh token com rotação/revogação via
  blacklist, `/me`. Migration Alembic real. 40 testes (unit + integração
  contra SQLite; validado manualmente também contra Postgres/Redis reais via
  Docker). `ruff`/`mypy --strict` limpos.

Durante essa implementação, um bug real de segurança foi encontrado e
corrigido no pacote `restaurant-security`: `require_role()` não conseguia
resolver `Depends(get_current_user)` quando o módulo usava `from __future__
import annotations` (a anotação virava string e o FastAPI não conseguia
avaliar a referência à closure `get_current_user`), fazendo o RBAC falhar
silenciosamente (parâmetro tratado como query, não como sub-dependency).
Corrigido removendo o `__future__ import` desse módulo especificamente.
